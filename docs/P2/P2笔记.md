# P2笔记

本文用于梳理 Project2 的关键执行路径，目标是回答三个问题：

1. 系统从启动到进入任务运行态的顺序是什么。
2. trap 从进入到返回的闭环如何成立。
3. timer 抢占、syscall 分发、调度切换如何衔接。

文中统一使用“触发条件 -> 跳转依据 -> 下一站”的结构描述。

---

## 1. 关键模块地图

### 1.1 启动与初始化
- `init/main.c`
- 负责初始化跳表、PCB、异常分发表、syscall 表、定时器与中断开关。

### 1.2 trap 入口与返回
- `arch/riscv/kernel/trap.S`
- `arch/riscv/kernel/entry.S`
- 负责设置 `stvec`、保存/恢复上下文、进入分发器、统一返回 `sret`。

### 1.3 分发与处理
- `kernel/irq/irq.c`
- `kernel/syscall/syscall.c`
- `kernel/sched/sched.c`
- `tiny_libc/syscall.c`
- 负责中断/异常分发、系统调用处理、时钟中断处理、调度与切换。

---

## 2. 主执行线（从 `main` 开始）

`main()` 关键顺序如下：

1. `init_jmptab()`
2. `init_task_info()`
3. `init_pcb()`
4. `time_base = bios_read_fdt(TIMEBASE)`
5. `init_locks()`
6. `init_exception()`
7. `init_syscall()`
8. `init_screen()`
9. `bios_set_timer(get_ticks() + TIMER_INTERVAL)`
10. `enable_interrupt()`
11. `enable_preempt()`
12. `while (1) { asm volatile("wfi"); }`

### 2.1 顺序约束

1. `init_exception()` 必须先于运行期 trap。
- trap 入口未注册时发生异常/中断会导致不可恢复错误。

2. 首次 `bios_set_timer(...)` 用于预约第一拍时钟事件。
- 该调用设置“到期时刻”，不是立即触发中断。

3. `enable_interrupt()` 与 `enable_preempt()` 分别对应不同层级使能。
- 前者涉及 `sstatus.SIE`。
- 后者设置 `sie` 中断允许位（实现中为全位开启，包含 `STIE`）。

4. 主循环仅保留 `wfi`。
- 语义是等待异步事件驱动执行流进入 trap。

---

## 3. trap 入口注册链

### 3.1 `init_exception()`

在 `kernel/irq/irq.c` 中：

1. 初始化 `exc_table[]`，设置：
- `exc_table[EXCC_SYSCALL] = handle_syscall`

2. 初始化 `irq_table[]`，设置：
- `irq_table[IRQC_S_TIMER] = handle_irq_timer`

3. 调用 `setup_exception()` 完成入口安装。

### 3.2 `setup_exception()`

在 `arch/riscv/kernel/trap.S` 中：

1. `la t0, exception_handler_entry`
2. `csrw CSR_STVEC, t0`
3. `li t0, SIE_STIE`
4. `csrs CSR_SIE, t0`

### 3.3 生效机制

触发条件 -> 跳转依据 -> 下一站：

1. 条件
- 发生同步异常（例如 `ecall`）或异步中断（例如 timer）。

2. 依据
- CPU 读取 `stvec`，进入 `exception_handler_entry`。

3. 下一站
- 在 `entry.S` 完成上下文保存与参数准备后，转入 C 分发器 `interrupt_helper`。

---

## 4. `exception_handler_entry` 入口细节

关键顺序：

1. `SAVE_CONTEXT`
2. `la ra, ret_from_exception`
3. `mv a0, sp`
4. `ld a1, OFFSET_REG_SBADADDR(sp)`
5. `ld a2, OFFSET_REG_SCAUSE(sp)`
6. `j interrupt_helper`

### 4.1 每条关键语句作用

1. `SAVE_CONTEXT`
- 将通用寄存器及 `sstatus/sepc/stval/scause` 保存到当前进程内核栈。

2. `la ra, ret_from_exception`
- 设置统一返回地址。
- 由于后续使用 `j`（无链接跳转），必须手工准备 `ra`。

3. 参数准备
- `a0`：`regs_context_t` 指针（当前 `sp`）。
- `a1`：`stval`。
- `a2`：`scause`。

4. `j interrupt_helper`
- 直接转入 C 分发器。

### 4.2 为什么 `la ra, ret_from_exception` 不能放在最后

1. `j interrupt_helper` 执行后，后续指令不会被顺序执行。
2. `j` 不会自动写返回地址，若不提前写 `ra`，无法保证回到统一返回口。
3. 该设计确保 C 分发链返回时落到 `ret_from_exception`，由该入口统一恢复并 `sret`。

---

## 5. C 分发器：`interrupt_helper`

核心逻辑：

1. `code = scause & ~SCAUSE_IRQ_FLAG`
2. 若是 IRQ：调用 `irq_table[code]`
3. 若是异常：调用 `exc_table[code]`
4. 非法编号回退到 `handle_other`

### 5.1 两条常用分支

1. syscall 分支
- `EXCC_SYSCALL -> handle_syscall`

2. timer 分支
- `IRQC_S_TIMER -> handle_irq_timer`

---

## 6. syscall 路径（用户态到内核态再返回）

### 6.1 用户态触发

`tiny_libc/syscall.c` 的 `invoke_syscall`：

1. `a0~a4` 传参
2. `a7` 传 syscall 编号
3. 执行 `ecall`

触发后陷入 trap，进入 `exception_handler_entry`。

### 6.2 内核处理

`kernel/syscall/syscall.c` 的 `handle_syscall`：

1. `fn = regs->regs[17]`（`a7`）
2. `syscall[fn](regs->regs[10], ..., regs->regs[14])`
3. 返回值写回 `regs->regs[10]`（`a0`）
4. `regs->sepc += 4`

### 6.3 `sepc += 4` 的必要性

1. `sret` 返回地址来自 `sepc`。
2. 不推进 `sepc` 会重复执行 `ecall`，导致持续陷入。

---

## 7. timer 抢占路径

### 7.1 timer 信号产生链

1. 内核设置下一拍：`bios_set_timer(next_deadline)`
2. 硬件计数达到比较值，置位 timer pending
3. 若中断使能满足，CPU 进入 trap

### 7.2 `handle_irq_timer`

`kernel/irq/irq.c` 中：

1. `bios_set_timer(get_ticks() + TIMER_INTERVAL)`
2. `do_scheduler()`

### 7.3 含义

1. 重设下一拍保证周期性中断持续发生。
2. 调度调用使中断具备“抢占切换”效果。

---

## 8. 调度与切换

### 8.1 `do_scheduler` 核心步骤

1. `check_sleeping()`：唤醒到期睡眠任务
2. 维护当前任务状态与队列
3. 选择下一个任务
4. 调用 `switch_to(prev, next)`

### 8.2 `switch_to` 切换语义

在 `entry.S` 中：

1. 保存 `prev` 的 callee-saved 寄存器与 `sp`
2. `sd sp, PCB_KERNEL_SP(a0)`
3. `ld sp, PCB_KERNEL_SP(a1)`
4. 恢复 `next` 上下文
5. `jr ra`

该过程完成“内核上下文”切换；用户态恢复在统一返回口完成。

---

## 9. 统一返回口：`ret_from_exception`

关键顺序：

1. `addi t0, sp, OFFSET_SIZE`
2. `sd t0, PCB_KERNEL_SP(tp)`
3. `RESTORE_CONTEXT`
4. `sret`

### 9.1 闭环含义

1. 保存更新后的内核栈位置到 PCB。
2. 恢复 trap 前寄存器状态。
3. 执行 `sret`，按 `sepc` 回到正确执行点。

---

## 10. 两条完整闭环（速查）

### 10.1 syscall 闭环

用户代码 -> `invoke_syscall` -> `ecall`
-> `exception_handler_entry`
-> `interrupt_helper`
-> `handle_syscall`
-> `ret_from_exception`
-> `sret`
-> 用户下一条指令。

### 10.2 timer 抢占闭环

`bios_set_timer + 中断使能`
-> timer 到期
-> `exception_handler_entry`
-> `interrupt_helper`
-> `handle_irq_timer`
-> `do_scheduler`
-> `switch_to`
-> `ret_from_exception`
-> `sret`
-> 新任务继续执行。

---

## 11. 排错清单（按链路定位）

1. trap 进不来
- 检查 `stvec` 是否指向 `exception_handler_entry`。
- 检查 `sstatus.SIE`、`sie.STIE` 是否开启。

2. syscall 后卡死
- 检查 `handle_syscall` 是否执行 `regs->sepc += 4`。

3. 无法回用户态
- 检查 `exception_handler_entry` 是否在跳分发器前设置 `ra = ret_from_exception`。
- 检查 `RESTORE_CONTEXT` 与 `sret` 前后栈状态。

4. timer 只触发一次
- 检查 `handle_irq_timer` 是否重设下一拍 `bios_set_timer(...)`。

5. 有中断但不抢占
- 检查 `handle_irq_timer` 是否调用 `do_scheduler()`。

---

## 12. 最小记忆骨架

1. `main` 完成初始化
2. `setup_exception` 安装 `stvec`
3. 设置首拍 timer，开启中断
4. `wfi` 等待事件
5. trap 进入 `exception_handler_entry`
6. `interrupt_helper` 分发
7. syscall 或 timer 处理
8. `ret_from_exception`
9. `sret` 返回任务

该骨架覆盖 P2 的核心执行逻辑，可直接用于实验汇报或调试定位。
